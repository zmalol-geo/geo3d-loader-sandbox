1. Overview

The Geo3D Loader workflow has a clear sequence. You can always go back and improve earlier steps — nothing is locked until you decide to publish.

Recommended order:
Legend (GVS) → Convert grids → Configure presentation → Preview → Publish

2. Create your geological legend (GVS)

Before converting anything, tell the system what your layers mean. This is done with the GVS Configurator (Generalised Vertical Section).

For each unit you define:

  • A clear name (this must match the root name of your ASCII files)
  • An RGB colour
  • A group (e.g. Superficial, Bedrock)
  • The correct stratigraphic order (usually youngest at the top)
Tip: Take a few extra minutes here. Good names and colours make the final model much easier for others to understand.

When you finish, download the layer_config.txt file. You will need it in the next step.

3. Convert ASCII grids to Geo3D

The asc-to-g3d converter turns your grids into optimised .g3d files and creates a basic project.json.

Important naming rules:

  • Each unit needs at least two grids: top + base, top + thickness, or base + thickness.
  • Use consistent suffixes (default: _T, _B, _TH).
  • The root name must match the name you used in the GVS legend.

Typical batch command

asc-to-g3d.exe batch -v -d "C:\path\to\your\grids" -c "C:\path\to\layer_config.txt"

After conversion, create a folder called assets, move all the new .g3d files into it, and place the generated JSON next to it (rename it to project.json).

You now have a working (but still basic) project that can already be loaded into the Geo3D Viewer.

4. Configure the project

Open the Project Configurator in your browser and upload the project.json you just created. The form lets you improve the experience without touching the JSON by hand.

Most important things to check or change:

  • Project title and a short, friendly description
  • Coordinate Reference System (for the UK usually EPSG:27700)
  • Layer colours and order
  • Which tools visitors can use (cross-sections, virtual boreholes, etc.)
  • Vertical exaggeration and grid settings
Write the description as if you are talking to a colleague who has never seen the model. A good description dramatically improves the first impression.

5. Preview & check

Before you publish, you want to see how the model actually looks and behaves in the Geo3D Viewer.

Current status: A dedicated “Preview in Geo3D” button that loads your model from temporary cloud storage is still under development. This is one of the most requested improvements.

Until the built-in preview is available, the practical approach is:

  • Double-check colours, order and CRS carefully in the Configurator
  • If you have access to a local or test instance of the Viewer, load the files there
  • Ask a colleague to look at the configuration with you

6. Publish and share

When you are happy with the model, the final step is to place the project.json and the assets folder on a web server that the Geo3D Viewer can reach.

The exact hosting method depends on your organisation. The documentation describes two common approaches used at BGS (object storage and static web server). For most users the simplest path is to contact the Geo3D team — they can advise on the best option for your situation.
